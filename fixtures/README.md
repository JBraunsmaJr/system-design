# Schema fixture corpus

One file per schema version the application has ever written. These are the
safety net for WS5-R5: every file any released version produced must continue
to open, with no field silently dropped.

## Do not hand-edit these files

They are generated by `scripts/generate-fixtures.sh`, which checks out each
historical commit into a temporary worktree and calls **that version's own**
`toDiagramFile`. A hand-authored fixture encodes what we currently believe an
old version wrote, and that belief is exactly what the compatibility test
exists to check.

Regenerate with:

    npm run fixtures:generate

Fixtures are byte-stable (the `updatedAt` timestamp is pinned), so regenerating
without a code change should produce no diff.

## Which versions actually shipped

| Schema    | Released in                   | Notes                                                                 |
|-----------|-------------------------------|-----------------------------------------------------------------------|
| 0.1 – 0.5 | never tagged                  | development only; files unlikely to exist outside a developer machine |
| 0.6       | v0.9, v0.91, v0.91.2, v0.91.3 | in users' hands                                                       |
| 0.7       | v0.92, v0.92.1                | current                                                               |

## Adding a version

Bump `SCHEMA_VERSION`, then append `"<version>:<commit>"` to the `VERSIONS`
array in `scripts/generate-fixtures.sh` and regenerate. Never remove an entry:
the corpus only grows.
